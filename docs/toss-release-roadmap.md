# HEX DANMAKU — 토스 미니앱 출시 로드맵

> 작성일: 2026-06-12 · 선행 문서: [toss-miniapp-release.md](toss-miniapp-release.md) (플랫폼 요건 리서치)
> 배경: 스프라이트 16×16 리스킨 완료(main). 경쟁력 평가에서 확인된 보강 과제를 출시 단계에 통합.
>
> **진단 요약** — 구조적 강점: 턴제(WebView 성능 리스크 無)·경량 번들·짧은 세션·시드 RNG·공정성 불변식.
> 보강 필요(유저+분석 합의): ① 스테이지 양 부족 ② 이펙트/연출/사운드 부족 ③ 재접속 이유 없음(리더보드·주간랭킹 부재) ④ 튜토리얼 구조 아님.

규모: S = 반나절~1일 · M = 2~4일 · L = 1주+ (Claude 세션 기준 체감치)

---

## Phase 1 — 게임성 보강 (플랫폼 무관, 지금 레포에서 바로 가능)

> 원칙: 플랫폼 전환(Phase 3) 전에 끝낸다. 지금의 빌드리스 개발 루프가 반복 작업에 가장 빠르고,
> 게임성은 어차피 어느 플랫폼이든 필요하다.

### 1-1. 인터랙티브 튜토리얼 (보강 ④) — **M** · 최우선
- 스테이지 1을 강제 가이드형으로 재설계: "이 셀을 탭" 하이라이트 → 입력 게이팅(지시한 이동만 허용) → 탄막 1발 피하기 → 포탈 진입까지 단계별.
- 신규 유저는 게이머가 아니라 토스 유입 일반인 — 첫 30초 안에 6방향 이동이 손에 익어야 함.
- 기존 `tip` 텍스트 시스템 → 단계형 시나리오 구조로 확장. 스킵 버튼 필수(재방문자).
- **완료 기준**: 처음 보는 사람이 설명 없이 스테이지 1을 클리어한다 (실제 1명 테스트).

### 1-2. 이펙트 · 연출 · 사운드 (보강 ②) — **M~L**
- **연출(juice)**: 탄막 소멸 파티클, 콤보 팝업 강조(x5/x10 임계), 피격/사망 화면 셰이크, 포탈 클리어 연출, 보스 페이즈 배너. CSS 애니 + SVG 파티클로 경량 구현(번들 영향 0).
- **사운드**: WebAudio 합성음(파일 없이 코드 생성 → 번들 0KB) 또는 초경량 SFX 몇 개. 이동/피킹/콤보/사망/클리어 5종부터.
  - ⚠️ 토스 규정 선반영: **on/off 토글, 백그라운드 진입 시 정지·복귀 시 재개, 광고/결제 중 일시정지**. 토글 기본값 ON 권장.
- **완료 기준**: 무음으로 플레이해도 어색하지 않던 게임이, 켜면 "타격감 있다"는 소리를 듣는다.

### 1-3. 콘텐츠 확장 (보강 ①) — **M~L**
- 스테이지 24 → **36~40개**: 기존 기믹(beams/pads/cracks/spikes/turrets/mines) 조합은 충분히 남아 있음. 에디터로 제작 → `validateStage` 2-ply + 공정성 시드 스윕(200~1000시드)으로 검증하는 기존 파이프라인 재사용.
- **확장팩 2탄(보스 존재감)** 여기에 포함: 보스 전용 스프라이트(리스킨 기반 마련됨) + HP 드레인 시각화 + 페이즈 배너. "버티기와 체감이 같다"는 플레이테스트 피드백 해소.
- 모바일 적 스테이지는 [fairness 교훈](superpowers/specs/) 준수: 연속 안전구역 풀만, rwall/lwall 금지.
- **완료 기준**: 별 72개 → 108개+, 보스전이 일반 생존 스테이지와 명확히 다르게 느껴진다.

### 1-4. 데일리 시드 챌린지 — 엔진 측 — **S~M** · 가성비 최고
- 엔드리스를 **날짜 기반 시드**(예: `YYYYMMDD`)로 돌리는 "오늘의 도전" 모드. 엔진이 이미 시드 RNG라 구현 저렴.
- 모두가 같은 보드 → 점수 비교가 공정 → Phase 3에서 토스 리더보드를 붙이는 순간 "오늘의 전국 순위"가 됨.
- 이 단계에서는 로컬 기록만 (일별 최고점 저장). SDK 연동은 3-3에서.
- **완료 기준**: 같은 날짜에 두 기기에서 동일한 탄막 시퀀스가 나온다 (시드 테스트 추가).

### 1-5. 포장 정비 — **S**
- "탄막"이 하드코어해 보이는 문제: 부제를 퍼즐 정체성으로 병기 (예: "한 칸의 두뇌 회피 퍼즐"). 메뉴/스토어 문구 정리.
- 네비바용 한글 미니앱 이름 + 브랜드 로고(픽셀 타이틀 활용) 확정 — 심사 요건이기도 함.

## Phase 2 — 리텐션 루프 설계 (보강 ③, 엔진 측 준비)

> SDK 없이 만들 수 있는 구조를 먼저 완성하고, Phase 3에서 토스 SDK로 갈아끼운다.

### 2-0. 코인 경제 개편 — **M** · 스펙 확정 ([2026-06-12-coin-economy-design.md](superpowers/specs/2026-06-12-coin-economy-design.md))
- 점수·화폐 분리: **점수 = 실력 지표, 코인 = 런 간 지속 화폐(광고/IAP 연결점)**.
- 스테이지 모드: 스킬 결제를 코인으로(뒤로 20/폭탄 30/정지 40, 런당 2회 제한), 클리어 보상(첫 클리어 별×20, 재클리어 별×5) + 필드 코인 픽업(5코인, 신규 스프라이트).
- 엔드리스/데일리: 현행 점수 차감 유지 → 리더보드에 결제력 개입 차단 (Phase 5 수익화의 전제).
- 별점 페널티(skillUses) 유지 — 남발 시 별·코인 보상이 같이 줄어드는 자기 균형.

### 2-1. 기록 체계 정리 — **S**
- 현재: `hi` 최고점 + 별점 → 확장: 모드별(엔드리스/데일리) 기록, 주간 베스트, 통산 통계(총 턴, 최다 콤보).
- 저장 추상화 레이어 도입(`window.HXSave` 등): 지금은 localStorage, Phase 3에서 Native Storage로 구현체만 교체.

### 2-2. 주간 랭킹 구조 — **S** (로컬) 
- 주차 키(`2026-W24`) 기반 기록 분리 — "이번 주 내 베스트" UI. 토스 리더보드 연동 시 주간 리셋 랭킹의 토대.

### 2-3. 복귀 보상 훅 — **M** (선택, 출시 후로 미뤄도 됨)
- 데일리 첫 클리어 보너스 점수, 연속 출석 표시 등 가벼운 것만. 과한 메타(재화/뽑기)는 이 게임 정체성과 안 맞음 — YAGNI.

## Phase 3 — 토스 플랫폼 전환 (선행 문서 B·C 체크리스트)

### 3-1. 정적 빌드 파이프라인 (B-1, 필수 전제) — **M**
- 인브라우저 Babel + CDN 개발빌드 제거 (심사 규정: eval 금지). 
- **`tools/shot.mjs`의 사전 트랜스파일 방식이 이미 프로토타입**: node에서 JSX→JS 변환 + IIFE 스코핑 + React UMD 번들링이 검증돼 있음. 이를 esbuild 기반 빌드 스크립트로 정식화 (React prod 빌드로 교체, 미니파이).
- 기존 빌드리스 개발 루프는 유지(개발=지금 방식, 배포=빌드) — 테스트 하니스 영향 없음.
- **완료 기준**: `npm run build` → 단일 정적 번들, 빌드 산출물로 전 스테이지 플레이 가능, 71+ 테스트 통과 유지.

### 3-2. 모바일 입력 1급화 + Safe Area — **M**
- 탭 이동은 있음 → 보강: 터치 타깃 크기, 스와이프 6방향 이동(선택), 키보드 힌트 UI를 모바일에선 숨김.
- Safe Area SDK 대응(노치/다이나믹 아일랜드), **OS 뒤로가기 제스처 비활성 + history 조작 금지** (심사 요건).
- 우상단 닫기 버튼, 모든 화면 나가기 경로.

### 3-3. 필수 SDK 5종 연동 (C) — **M~L**
| SDK | 연결 지점 |
|---|---|
| 게임 로그인 | 유저 식별 해시 → 기록 귀속 |
| **리더보드** | 엔드리스 + **데일리 시드(1-4)** + 주간(2-2) 제출 |
| Safe Area | 3-2와 함께 |
| Native Storage | 2-1 저장 추상화의 구현체 교체 (별점/기록/설정 이관 + 기기 변경 시 유지) |
| Analytics | 첫판 이탈 지점·튜토리얼 완주율·데일리 참여율 — Phase 1 보강의 효과 측정 |
- DEV 에디터 프로덕션 번들 제외(B-3), 번들 ≤100MB 확인(현재 여유 큼).

## Phase 4 — 심사 · 출시 (선행 문서 D·F)

- **D 체크리스트 최종 점검**: 로딩 10초/상호작용 2초, 닫기 버튼, 네비바(로고+한글명), Safe Area, 뒤로가기 비활성, 사운드 규칙(1-2에서 선반영), wss only(해당 없음 — 네트워크 미사용), eval 금지(3-1에서 해소).
- **F 프로세스**: 콘솔 등록 → 샌드박스 번들 업로드 → QR로 실기기 테스트(여기서 3-2 입력감 재검) → 검수 요청(1버전씩, 최대 3영업일) → 출시.
- 출시 빌드 스모크: `tools/shot.mjs`를 빌드 산출물 대상으로 돌려 메뉴/엔드리스/스테이지 자동 캡처 확인.

## Phase 5 — 출시 후 (선택)

- Analytics 지표 모니터링: 첫판 이탈률·D1 복귀·데일리 참여율 → 1-1/1-4 효과 검증 후 보강.
- 수익화(E)는 **보류 권장**: 사업자등록 필요. 리더보드·푸시·공유보상은 사업자 없이 가능하니 먼저 지표 확인.
- 푸시: "오늘의 챌린지가 갱신되었습니다" — 데일리 시드와 묶으면 자연스러운 복귀 메시지.

## 순서 요약 & 의존성

```
Phase 1 (게임성: 튜토리얼 → 연출/사운드 → 콘텐츠+보스 → 데일리 시드 → 포장)
   ↓
Phase 2 (코인 경제 개편 → 기록 추상화 → 주간 구조)   ← 2-0은 Phase 1과 병행 가능 (스펙 확정됨)
   ↓
Phase 3 (정적 빌드 → 모바일 입력/SafeArea → SDK 5종)   ← 2-1 추상화가 Native Storage 이관을 쉽게 함
   ↓
Phase 4 (심사 점검 → 샌드박스 → 검수 → 출시)
   ↓
Phase 5 (지표 → 보강 → 수익화 검토)
```

- **착수 추천**: 2-0 코인 경제(스펙 확정·수익화 전제) → 1-1 튜토리얼(이탈률의 상류) → 1-4 데일리 시드(최저 비용·최대 리텐션 기대). 
- 각 항목은 기존 superpowers 워크플로우(스펙 → 플랜 → TDD)로 개별 진행.
- 플랫폼 요건은 변동 가능 — Phase 3 착수 시 `apps-in-toss-ax` MCP 설치해 최신 문서 재확인 (`npm i -g @apps-in-toss/ax` → `claude mcp add apps-in-toss -- ax mcp start`).
