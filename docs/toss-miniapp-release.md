# 토스 미니앱(앱인토스) 출시 정리 — HEX DANMAKU

> 작성일: 2026-06-09 · 대상: HEX DANMAKU (`d:\00.project\hex\hex-danmaku`)
> 성격: **출시 준비 리서치 요약**(구현 아님). 토스 "앱인토스(Apps in Toss)" 게임 미니앱 경로 기준.
> ⚠️ 플랫폼 요건은 변할 수 있음 — SDK 패키지명·CLI·Granite 스캐폴딩 등 **정확한 디테일은 출시 착수 시 [앱인토스 개발자센터](https://developers-apps-in-toss.toss.im/) + `apps-in-toss-ax` 툴킷으로 재확인**.

---

## 0. 한눈에

- 앱인토스 = 토스 앱 **내부 WebView 미니앱**. 프레임워크 **Granite** + 앱인토스 **SDK** 기반. 웹(React) 게임은 WebView 경로에 매핑됨.
- 배포는 외부 호스팅(Firebase/구글 등)이 **아님** → 토스 **콘솔에 앱 번들 업로드 → 검수 → 토스가 노출**.
- 우선순위: **B(정적 빌드+SDK 전환) → C(필수 SDK 5종) → D(심사 체크리스트) → F(검수/출시).** 수익화·사업자(E)는 선택.

---

## A. 플랫폼 구조 (먼저 이해)

| 항목 | 내용 |
|------|------|
| 형태 | 토스 앱 안에서 도는 앱인앱(App-in-App) WebView 미니앱 |
| 프레임워크 | **Granite** (v1.0+) + 앱인토스 SDK (WebView / React Native 지원) |
| 배포 | 콘솔에 **앱 번들 업로드** → 검수 → 출시 (외부 웹호스팅 불가) |
| 디자인 | 게임은 **TDS(토스 디자인 시스템) 강제 아님**. TDS는 비게임 미니앱 필수 |

> 앞서 검토했던 "Firebase/구글 호스팅 + PWA" 경로는 **이 경로엔 해당 없음.** 토스 런타임 안에서 동작.

---

## B. 코드/빌드 필수 변경 (현재 프로젝트 기준)

현재 구조: 빌드 스텝 없이 `@babel/standalone`로 **브라우저에서 JSX를 매번 변환** + React **개발 빌드**를 CDN 로드. `.jsx`는 ES 모듈이 아니라 전역(`window.HX`…)+로드 순서 의존.

1. **브라우저 내 Babel 제거 = 플랫폼 규칙상 필수** (선택 아님)
   - 심사 규정: *"eval 등 외부 코드 실행 금지"*, *"SSR 금지 — CSR/SSG만 허용"*.
   - → 인브라우저 Babel 변환 + CDN 개발빌드 부적합. **빌드 파이프라인으로 정적 CSR 번들** 생성 필요.
   - 최소 경로: `esbuild`로 각 `.jsx` 트랜스파일+미니파이 후 일반 `<script>`(순서 유지). 정석: Granite/앱인토스 web SDK 구성으로 마이그레이션.
2. **앱인토스 SDK / Granite로 프로젝트 구성·번들**.
3. 앱 번들 **≤100MB**(압축 해제 기준), 큰 에셋은 CDN/외부 + lazy load. *(현재 픽셀아트라 가벼움 ✓)*
4. **인게임 DEV 에디터는 프로덕션 번들에서 제거/게이트** (메뉴 "에디터 ✎"는 DEV 기능).

---

## C. 게임 필수 SDK 5종 (심사 통과 기본 조건)

| # | SDK | 용도 | 현재 프로젝트 영향 |
|---|-----|------|--------------------|
| 1 | **게임 로그인** | 가입/약관 없이 유저 식별 해시 | 신규 연동 |
| 2 | **리더보드** | 점수 제출·랭킹(리텐션) | 신규 연동(현재 `hi` 최고점 → 리더보드로) |
| 3 | **Safe Area** | 노치/다이나믹아일랜드 대응 | 레이아웃 보정 |
| 4 | **Native Storage** | 진행도/설정 저장 | **현재 localStorage 세이브(별점/최고점/에디터 오버라이드)를 이관** |
| 5 | **행동 분석(Analytics)** | 이벤트 트래킹·A/B | 신규 연동 |

## D. 게임 심사 체크리스트

- 최초 화면 **10초 내** 로딩, 상호작용 지연 **2초 이내**
- 우상단 **닫기 버튼** 동작, 네비바에 **브랜드 로고 + 한글 미니앱 이름**
- **Safe Area** 준수, 모든 화면에 나가기 경로
- **OS 뒤로가기 제스처 비활성**, 브라우저 history 조작 금지
- 웹소켓 사용 시 `wss://`만, **eval 금지**, 불법·선정성 콘텐츠 금지
- **사운드**(넣을 경우): on/off 토글 + 광고·결제 중 일시정지 + 백그라운드 시 정지/포그라운드 복귀
  - *현재 무음 → 사운드 추가 여부 결정 필요. 무음이면 이 항목 부담 적음.*
- 유저 식별 키 기반 데이터 지속(앱 종료·재실행, 기기 변경 후에도 진행도 유지)

---

## E. 수익화 (선택 — 사용 시 사업자등록 필요)

- 기능: 인앱광고 / 인앱결제 / 토스페이 / 프로모션(토스포인트) / 공유 보상
- **사업자등록 필수**(개인 또는 법인). 제약:
  - 업종이 미니앱 서비스 타입과 **일치**해야 함
  - **면세사업자 불가**, 세금계산서 발행 불가 사업자 운영 불가
  - 서류 심사 **1~2영업일**
- **수익화 없이도 출시 가능** — 리더보드·푸시·게임 프로필·공유보상은 **사업자 없이** 사용 가능
- 참고: 토스 자료상 마케팅 기능 적용 미니앱이 평균 MAU **1.7~10.6배** 높았다고 함

---

## F. 출시 프로세스 (콘솔)

1. 콘솔 계정 생성 + 미니앱 등록
2. 디자인 준비(앱빌더 또는 피그마)
3. SDK 설치 + 미니앱 개발
4. **샌드박스 앱**으로 테스트(번들 업로드 → QR로 토스 앱에서 확인)
5. 콘솔에서 **검수 요청** (한 번에 1버전만 제출)
6. 검수 **최대 3영업일**(보통 2~3일). 반려 시 사유 확인 → 수정 번들 재업로드
7. 승인 후 **출시 → 전체 사용자 즉시 반영**. 이후 크래시 로그·API 실패·지표 모니터링, 업데이트/롤백은 동일 검수 절차

## 출시까지 작업 묶음 (요약)

- [ ] **B-1** 정적 빌드 도입(인브라우저 Babel 제거, React prod 번들) — *전제*
- [ ] **B-2** 앱인토스 SDK/Granite로 프로젝트 구성
- [ ] **B-3** DEV 에디터 프로덕션 제외, 번들 ≤100MB 확인
- [ ] **C** 필수 SDK 5종 연동(로그인·리더보드·Safe Area·Native Storage·Analytics) + localStorage→Native Storage 이관
- [ ] **D** 심사 체크리스트 충족(닫기버튼·네비바·Safe Area·뒤로가기 비활성·사운드 규칙·로딩 10초)
- [ ] **F** 콘솔 등록 → 샌드박스 테스트 → 검수 요청 → 출시
- [ ] **E**(선택) 수익화 결정 → 필요 시 사업자등록
