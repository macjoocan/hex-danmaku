# 코인 경제 개편 — 점수·화폐 분리 (디자인 스펙)

> 작성일: 2026-06-12 · 승인: 유저 (대화에서 디자인 승인)
> 배경: 현재 스킬 3종(뒤로가기/폭탄/정지)을 **점수 차감**으로 사용 → ① 점수가 무한 재생 자원이라 후반 남발 가능 ② 점수는 팔 수 없어 광고/IAP 연결 불가. 로드맵(`docs/toss-release-roadmap.md`) Phase 2의 선두 과제.

## 목표

점수와 화폐를 분리한다. **점수 = 순수 실력 지표(리더보드용), 코인 = 런 간 지속·소비되는 화폐(광고/IAP 연결점)**. 스테이지 모드는 코인 경제로 전환하고, 엔드리스(및 향후 데일리)는 현행 점수 차감을 유지해 리더보드 무결성을 지킨다.

## 1. 화폐 구조 (모드별 분리)

| | 스테이지 모드 | 엔드리스 / 데일리(향후) |
|---|---|---|
| 스킬 지불 | **코인** (런 간 지속 지갑) | **점수 차감** (현행 유지, 변경 없음) |
| 점수 | 화폐 기능 제거 — 기록·표시 전용 | 점수=자원 긴장감 유지, 코인 개입 없음 |
| 수익화 연결 | 코인 = 광고/IAP 판매 단위 (Phase 5, 이번 범위 밖) | 결제가 순위에 영향 주지 않음 |

## 2. 코인 획득

- **클리어 보상**: 첫 클리어 = 획득 별 × 20코인, 재클리어 = 별 × 5코인(파밍 감쇠). "첫 클리어 여부"는 기존 별점 저장(`hex_stars`)에 해당 스테이지 기록이 있는지로 판정.
- **필드 코인 픽업**: 신규 픽업 종류 `cn` = 5코인. **(구현 중 설계 보정)** 기존 픽업 스폰(`tryItem`)은 엔드리스 전용임이 확인됨 — 다른 픽업을 스테이지에 풀면 스테이지 밸런스·공정성 전제가 흔들리므로, **스테이지 전용 코인 스포너 `tryCoin`을 분리**(전용 노브 `coin.spawnChance: 0.08, coin.max: 2`). 엔드리스 픽업 풀은 변경 없음. 신규 16×16 동전 스프라이트 1종(리스킨 스타일: 다크 아웃라인+셰이딩, 금화 — gem·star와 실루엣 구분: 원형+C 각인).
- **연출**: 코인 획득 시 `+5` 플로트(금색), 클리어 화면에 "+N 코인" 합산 표시. HUD에 지갑 잔액 표시(스테이지 모드만).
- 보상 수치는 `BAL.coin`(신규 섹션)으로 에디터 밸런스 탭에서 조정 가능: `clearPerStar:20, repeatPerStar:5, pickupValue:5`.

## 3. 아이템 사용 (인게임 구매 + 회수 제한)

- 스킬 버튼 3종·발동 로직 유지, **스테이지 모드에서만 지불 수단을 코인으로 교체**: 뒤로가기 20 / 폭탄 30 / 정지 40코인 (초안, `BAL.skill`에 `undoCoin/bombCoin/freezeCoin` 추가).
- **런당 회수 제한: 스킬당 2회** (`BAL.skill.usesPerRun:2`, 0=무제한). 엔드리스는 제한 없음(현행).
- 버튼 UI: 스테이지 모드에서 가격을 "N🪙"로, 잔여 횟수(2/2) 표시. 잔액·횟수 부족 시 비활성.
- **별점 페널티 유지**: `rateStage`(skillUses 기반) 변경 없음 — 아이템을 쓰면 클리어는 쉽지만 별·코인 보상이 줄어드는 이중 견제.
- **undo와 코인**: undo는 이전 상태를 복원하되 코인 차감은 복원된 상태에 적용(현행 점수 차감과 동일한 의미론). 폭탄/정지에 쓴 코인은 undo로 **환불되지 않음**(hist 상태의 coins가 이미 차감 전 값이므로, undo 시 hist.coins에서 undo 비용만 차감).

## 4. 아키텍처

- **엔진 순수성 유지**: 코인을 게임 상태로 운반.
  - `HXS.initStage(idx)` → `s.coins = HXS.loadCoins()`, `s.skillLeft = { undo:2, bomb:2, freeze:2 }` 초기화.
  - `doUndo/doBomb/doFreeze(s)`: `s.mode === 'stage'`면 코인·횟수 검사/차감, 아니면 현행 점수 검사/차감. 순수 함수 유지(테스트 용이).
  - 런 종료(클리어/사망/이탈)·클리어 보상 합산 시 app.jsx에서 `HXS.saveCoins(...)` 한 번 호출. `_test`(에디터 테스트플레이) 런은 지갑에 반영하지 않음.
- **지갑**: stages.jsx에 `loadCoins()/saveCoins(n)` (localStorage `hex_coins`, `loadStars` 패턴). 로드맵 2-1 저장 추상화의 첫 적용 대상 — 이후 Native Storage로 구현체만 교체.
- **에디터**: BAL_FIELDS에 coin 섹션·스킬 코인 가격·usesPerRun 노출. `buildBalance` 클램프에 coin 필드 음수 방지 추가.
- **신규 스프라이트**: resources.jsx에 `coin` 픽셀 엔트리(16×16, px 1.5, warnStroke) + sprites.jsx에 CoinSprite(다른 픽업과 동일 패턴) + 렌더 배선.

## 5. 테스트 (RED→GREEN)

- 스테이지 모드: 코인 차감 / 잔액 부족 시 불발 / 회수 제한 도달 시 불발 / 점수는 불변.
- 엔드리스 모드: 현행 점수 차감 동작 회귀 없음 (기존 테스트 유지 + 모드 분기 케이스).
- undo: 비용 의미론(환불 없음) 검증.
- 클리어 보상: 첫/재클리어 분기, 별 비례 계산, `_test` 런 지갑 미반영.
- 코인 픽업: 획득 시 s.coins 증가·픽업 제거, 엔드리스 미스폰.
- 지갑: save→load 라운드트립, 비정상 값(NaN/음수) 가드.
- 공정성 영향 없음: 코인 픽업은 비치명 오브젝트(기존 픽업과 동일 취급)라 fairness 테스트 변경 불요.

## 범위 밖 (명시)

- 광고 시청 보상·코인 팩 IAP·클리어 2배 광고 → Phase 5 (토스 SDK + 사업자 결정 후). 이번 작업은 그 연결점(코인)만 만든다.
- 입장 전 장착(로드아웃) UI, 신규 아이템 종류 추가 — YAGNI.

## 수용 기준

- 스테이지 모드에서 스킬이 코인으로만 결제되고(점수 불변), 런당 스킬별 2회 제한이 걸린다.
- 엔드리스는 동작·체감 변화가 전혀 없다.
- 클리어 시 별 비례 코인이 지급되고 재실행해도 지갑이 유지된다.
- 코인 픽업이 스테이지 보드에 스폰·획득되고 새 동전 스프라이트로 렌더된다.
- `npm test` 전체 + JSX 체크 통과, 에디터에서 코인 밸런스 수치 조정 가능.
