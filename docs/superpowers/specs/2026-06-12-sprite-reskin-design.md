# 스프라이트 전체 리스킨 — 「전설의검」 스타일 (디자인 스펙)

> 작성일: 2026-06-12 · 승인: 유저 (대화에서 디자인 승인 완료)
> 레퍼런스: `assets/maxresdefault.jpg` (전설의검 프로모션 이미지 — 레포에 커밋하지 않음)
> 제작 방식: **A안 — Claude가 그리드+컬러맵을 직접 리드로우** (시각 루프). 품질 부족 시 PixelLab(B안) 전환 가능 — 그리드 구조가 같아 매몰 비용 없음.

## 목표

현재 8×8 추상 도형 위주의 스프라이트를, 레퍼런스처럼 **치비 비율 + 다크 아웃라인 + 셰이드 램프**가 있는 16×16급 픽셀아트로 전면 교체한다. 게임 로직·렌더 구조([resources.jsx](../../../resources.jsx)의 그리드+컬러맵 시스템)는 그대로 유지한다.

## 1. 스타일 가이드

| 항목 | 규칙 |
|------|------|
| 그리드 | 적·탄막·픽업·기믹 **16×16** (현재 8×8), 히어로 **16×20** (현재 12×15) |
| 렌더 배율 | `px≈1.5` → 약 24px (헥스 반지름 `SZ=23`, 폭 약 40px의 60%). 답답하면 배율만 조정 |
| 아웃라인 | 전 스프라이트 1px 외곽선. 순검정 대신 **본체 색의 진한 톤** (예: 드론 → 짙은 와인색) |
| 셰이딩 | 광원 좌상단 고정. 색마다 본색 + 하이라이트 + 셰이드 **2~3단 램프** |
| 캐릭터화 | 살아있는 것(히어로·드론·체이서·바운서·런저)은 **눈/표정** 부여. 히어로는 머리 비중 50%+ SD 비율 |
| 색 정체성 | **기존 색 코드 유지** (게임플레이 가독성 최우선): 드론=빨강·핑크, 프로즌=파랑, 체이서=마젠타, 바운서=시안, 런저=오렌지, 지뢰=노랑, 빔=틸. 채도·명도만 레퍼런스 톤으로 보정 |
| warn 시스템 | `warnStroke` / `warnMap` 그대로 유지 (16×16 그리드에서도 동일하게 동작) |

## 2. 대상

- **픽셀 리드로우 18종**: player, drone, droneFz, chaser, bouncer, lunger, turret, star, bomb, tp, hint, gem, portal, spike, pad, mine, beam, explode
- **벡터 유지 2종**: wall, crack — 헥스 모양 채우기 구조라 벡터 유지, 새 톤에 맞춰 색만 조정
- droneFz는 drone과 **같은 그리드, 팔레트만 교체** (현행 구조 유지)
- pad는 동쪽(→) 기준으로 그림 (스프라이트가 dir별 회전 — `PAD_DEG` 참조)

## 3. 작업 방식 (시각 루프)

1. 스프라이트 1종 리드로우 → `node tools/extract-sprites.mjs` → **추출 PNG를 Claude가 직접 보고** 수정 반복
2. 카테고리 완료 시 인게임 합성 확인: Playwright **헤드리스 node 스크립트**로 보드 스크린샷 (MCP가 세션에 안 잡히는 경우 대비)
3. 매 카테고리마다 `npm test`(68개) + `node tests/_babelcheck.mjs` 통과 확인 후 커밋

커밋 단위 (3회 예상): ① 캐릭터·적 (player, drone, droneFz, chaser, bouncer, lunger, turret) → ② 픽업 (star, bomb, tp, hint, gem) → ③ 기믹·오브젝트 (portal, spike, pad, mine, beam, explode + wall/crack 색 조정)

## 4. 리스크와 완화

| 리스크 | 완화 |
|--------|------|
| 인게임 리소스 에디터가 8×8 가정일 수 있음 | 계획 단계에서 [editor.jsx](../../../editor.jsx) 확인, 필요 시 16×16 편집 지원 소폭 수정 |
| 16×16이 셀 안에서 답답해 보임 | `px` 배율만 낮추면 됨 (그리드 재작업 불필요) |
| 손그림 품질 한계 | 시각 루프로도 부족하면 PixelLab MCP(유료) 전환 — PNG→그리드 변환 스크립트만 추가하면 됨 |
| 테스트 영향 | resources.jsx는 테스트에서 stub — 깨질 위험 낮음. 그래도 매 커밋 전 전체 테스트 실행 |

## 수용 기준

- 18종 모두 16×16(히어로 16×20) 그리드로 교체, 보드 크기(~24px)에서 실루엣·색 정체성이 한눈에 구분됨
- 전 스프라이트 다크 아웃라인 + 2~3단 셰이딩 적용, 살아있는 5종은 표정 있음
- `npm test` 68개 + JSX 체크 8/8 통과, 인게임 에디터에서 새 그리드 편집 가능
- 인게임 스크린샷에서 워닝(빨간 글로우)·프로즌 팔레트·pad 회전이 정상 동작
