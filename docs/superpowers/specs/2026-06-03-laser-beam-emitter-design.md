# 레이저 빔 방출기 (`beams`) — 설계 문서

> 작성일: 2026-06-03 · 대상: HEX DANMAKU (`d:\00.project\hex\hex-danmaku`)
> 상태: 설계 확정 → 이후 writing-plans로 구현 계획 작성
> **의존**: 확장팩 1탄 엔진(필드 기믹 `turret`/`pad`/`crack`, 기존 `lasers` 컬럼 타격)과 인게임 에디터가 이미 존재.

---

## 1. 목표 & 범위

에디터/스테이지에 **배치하는 새 필드 기믹** — 세로 컬럼을 한방에 지지는 "레이저 빔 방출기".
방출기 셀에서 상·하 방향으로 컬럼 전체를 타격하며, 발사 한 턴 전에 점선으로 예고한다.

### 기존 시스템과의 관계

- **기존 보스 레이저** (`lasers: [{c, charge}]`, [engine.jsx](../../../engine.jsx) 레이저 블록): `np.laser`로 스폰되는 **1회성** 위협. `charge` 2턴 카운트다운 후 컬럼 전체 타격(`finalC === l.c`), 발사 후 제거. 에디터 배치 불가.
- **신규 빔 방출기** (`beams`): **영속적**으로 배치되는 필드 기믹. 발사 후 **재장전(쿨다운)** 한다. 생명주기가 달라 별도 배열로 둔다. **컬럼 타격 판정(`finalC === c`)은 기존 레이저와 공유**한다.
- **포대**(`turrets`)와의 차이: 포대는 단단하고 바로 아래로 단발을 쏘며 전역 시계(`t % period`)로 동작. 빔은 비-솔리드이고 컬럼 전체를 일격하며 방출기별 쿨다운으로 동작.

### 설계 철학 (불변 제약 — 확장팩과 동일)

1. **항상 회피 가능** — 매 턴 안전한 이동지 최소 1개 보장. 빔이 모든 도달가능 컬럼을 동시에 덮어선 안 된다.
2. **결정론 + 예고** — 발사 한 턴 전 점선 예고. RNG 즉사 없음.
3. **레지스트리/테이블 관용구 재사용** — `RES`·필드 기믹 배열·tick 인라인 처리·`tests/*.test.mjs` 하니스를 그대로 따른다.

### 비목표 (1차 제외)

- 세로(상/하) 외 방향(가로/대각). 1차는 **컬럼(세로)만**.
- 벽에 막혀 그림자를 만드는 빔. 1차는 **컬럼 전체 관통**(벽 무시 — 기존 레이저와 동일).
- 빔이 탄/적을 제거하는 정화 효과. 1차는 **플레이어만 즉사**.
- 에디터에서 period 슬라이더 조절. 1차는 **기본 period=4 고정**(나중에 추가 가능).

## 2. 데이터 모델

### 스테이지 def (stages.jsx STAGES / 에디터 저장)

```js
beams: [{ r, c, period, phase? }]
```
- `r, c`: 방출기 위치. 컬럼 전체 관통이므로 타격 판정에는 `c`만 쓰이고 `r`은 방출기 스프라이트 위치(시각).
- `period`: 쿨다운 주기(기본 4). 발사 간격.
- `phase`(선택): 초기 오프셋 — 여러 방출기 발사 시점을 엇갈리게 해 공정성 확보.

### 런타임 상태 (initStageDef, stages.jsx)

```js
beams: (def.beams || []).map(b => ({ ...b, cd: (b.period || 4) - (b.phase || 0) }))
```
- `cd`: 발사까지 남은 카운트다운. 초기값으로 첫 발사가 turn 1에 터지지 않도록(예고 보장) period 기반 + phase 엇갈림.
- `initState`(엔드리스)에도 `beams: []` 추가(엔드리스엔 미사용, 일관성).

### 솔리드성

방출기는 **비-솔리드**(통과 가능 타일). 휴면 중엔 그 위에 서 있어도 되지만 발사 턴에 그 컬럼에 있으면 즉사. 탄막은 통과(`block`에 미포함). `GIMMICKS` 메타 테이블에 `beam: { blocksMove:false, blocksBullet:false, lethal:'whenFiring' }` 항목 추가(문서용 메타).

## 3. tick 상태머신 (engine.jsx — 기존 laser 블록 인접)

정지(`s.fz > 0`) 중엔 멈춤(기존 레이저와 동일 규칙). 매 턴 방출기마다:

```
cd -= 1
cd === 1  → 점선 예고(다음 턴 발사). 렌더용 telegraph set에 컬럼 c 추가.
cd <= 0   → 발사: finalC === beam.c 이면 beamHit = true.
            컬럼 플래시 evt push({ ty:'beam', c }). cd = period 로 리셋.
```

- 발사/예고 모두 **방출기별 `cd`**로 관리(전역 시계 아님). 결과 `beams`는 갱신된 `cd`로 다음 상태에 반환.
- 충돌 합치기: `const ov = stepIn || stepEnemy || hitBullet || hitEnemy || hitSpike || laserHit || beamHit;`
  - 가능하면 기존 `laserHit`와 `beamHit`를 "발사 중인 컬럼 집합"으로 모아 `finalC` 한 번에 판정(중복 로직 최소화).
- 타이밍: 예고 턴(`cd===1`)에 컬럼이 점선으로 보이고, 발사 턴(`cd===0`)에 플레이어가 **이동 후 위치(`finalC`)** 기준으로 판정 → 컬럼을 벗어나면 회피. 기존 레이저와 동일한 "예고→발사, 컬럼 이탈로 회피" 규칙.

## 4. 공정성 (tests/fairness.test.mjs)

- **단일 빔**: 어떤 컬럼/period라도 매 턴 안전 컬럼이 도달 가능해야 함 → 전용 케이스 추가(2-ply 룩어헤드 시뮬).
- **여러 빔**: 같은 턴에 모든 도달가능 컬럼을 덮으면 불공정 → `phase`로 엇갈리는 게 스테이지 설계 책임. 빔을 포함한 시연 스테이지(있다면)를 시드 1..40 스윕에 포함.
- `validateStage`(editor-core)는 `tick`으로 시뮬하므로 빔이 **자동 반영** — 에디터 "검증" 버튼이 빔 배치도 그대로 평가.

## 5. 에디터 (editor.jsx)

- `PALETTE`에 **`beam` 도구** 추가. 라벨 "레이저". 클릭 시 `{ r, c, period: 4 }` 배치, 같은 셀 재클릭/지우개로 제거.
- `place()`의 `removeAt` 목록과 도구 분기에 `beams` 추가. `blankDef()`에 `beams: []` 포함.
- `EditorBoard`에 방출기 셀 색 표시(예: 시안 계열).
- period 조절 UI는 1차 생략(기본 4). 커스텀 스테이지 저장/검증/테스트플레이에 자동 포함(JSON 직렬화는 기존 deepMerge/serialize가 배열을 그대로 처리).

- 범례에 "레이저 방출기" 항목 추가(기존 보스 광선 범례와 구분되는 아이콘).
- 시각 동작은 `npm test` 범위 밖 → 수동 QA.

## 7. 테스트 (TDD, headless · vm 하니스)

`tests/beams.test.mjs`(또는 기존 파일 확장):

1. **사이클**: 방출기 cd 카운트다운 → `cd===1` 예고 상태 → `cd<=0` 발사 → 발사 후 `cd === period`(쿨다운 리셋) 확인.
2. **타격**: 발사 턴에 같은 컬럼(`finalC === c`)이면 `ov === true`, 다른 컬럼이면 안전.
3. **정지**: `fz > 0` 동안 `cd` 불변(발사 안 함).
4. **벽 관통**: 컬럼에 벽/포대가 있어도 같은 컬럼이면 즉사(벽 무시).
5. **공정성**: 단일 빔 스테이지가 매 턴 안전 이동 보장(fairness 하니스).

모든 테스트는 RED(실패 먼저) → GREEN. 기존 57+ 테스트 무회귀 확인.

## 9. 확정된 결정

1. **이름**: 내부 키 `beams`, 도구/UI 라벨 "레이저(방출기)". 기존 보스 `lasers`(광선)와 구분.
2. **솔리드**: 비-솔리드(통과 가능, 발사 컬럼에 있을 때만 치명).
3. **period**: 기본 4 고정, 에디터 슬라이더는 1차 생략.
4. **방향/관통/타격**: 세로 컬럼 · 벽 관통(컬럼 전체) · 플레이어만 즉사.
5. **발사 리듬**: 쿨다운(발사 후 휴식 → 예고 → 발사 반복), 정지 중 멈춤.
